Built in the open

A tool worth keeping
belongs to its users.

FireCraft is an independent, community project. It exists because a productive way of working disappeared when its software did — and because the ideas underneath it were worth preserving, not the licence server.

Mission Clean room Roadmap Governance License Contribute

Mission

Preserve the workflow,
rebuild the software.

Hybrid vector-and-bitmap editing, layered documents, and web-ready output were good ideas. FireCraft rebuilds that way of working on a modern foundation: a Rust engine, a native application, a browser build, and automation that shares one command authority.

Portable

Native and WebAssembly from one workspace, with no runtime service dependency.

Editable

Documents stay documents. Unknown data survives a save instead of being dropped.

Scriptable

The GUI, CLI, scripting host, bridge, and MCP server drive the same commands.

Honest

Every claim on this site is labelled available, preview, in development, or planned.

Clean-room policy

Behaviour may be studied.
Code may not be copied.

The project is a reimplementation, not a redistribution. Reference material is documentation and observed behaviour only.

No Adobe code

No decompilation, no copied source, no extracted binaries. Implementation comes from the published file format and observed behaviour.

No Adobe assets

Artwork, icons, and screenshots on this site are the project's own. Nothing from a commercial install enters the repository.

Names only as reference

Adobe, Fireworks, Photoshop, Illustrator, and Macromedia are named to describe compatible workflows and formats, not to imply affiliation.

◆

Why say this out loud? Because a reimplementation is only legitimate if the provenance is checkable. The repository's attribution ledger and decision records exist so anyone can audit where every asset and behaviour came from.

Roadmap

Where the work is now

The task board is the authority; this is the shape of it. Phases overlap in practice, and dates are deliberately absent.

  • Foundation

    Document engine and format fidelity

    Layered Fireworks PNG round-trip, vector and bitmap object model, text, effects, formats, and the command registry.

    Available
  • Breadth

    Formats, export, and automation

    Raster and vector interchange, animated GIF, web export, headless CLI, scripting, bridge, and MCP surfaces.

    Available
  • Depth

    Daily-driver canvas

    Every registered command reachable from the GUI, selection-aware menus, transform and path workflows, and regression gates.

    In development
  • Shell

    CS6-inspired workspace fidelity

    Movable and collapsible panels, persisted layout, contextual panels, and the remaining panel inventory.

    In development
  • Reach

    Platform packaging and release breadth

    Windows and macOS packaging, reproducible artifacts, and publishable builds — only after each target is built and tested.

    Planned

Governance

One repository,
reviewable decisions.

Substantial design choices are written down as decision records before or alongside the code. The gate — formatting, linting, tests, format corpus, WASM build, and documentation checks — must pass before a change lands.

  • Conventional commits and reviewable change sets
  • Rising-only parity floors: a minimum bar never moves down
  • Fuzz anchors for every hostile-input surface
  • 130 decision records covering architecture and process

How to judge the project

Read the tests, the decision records, and the gap register rather than the marketing copy — including this page.

If a claim here cannot be traced to source, tests, or a published release, treat it as a defect and report it.
