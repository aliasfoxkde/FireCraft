Capability reference

Everything the editor does,
and how sure we are.

Grouped by workflow, with a state label on each area. Available means it ships in a published build; Preview means it works with documented limits; In development means it is being built now.

01 · Document

Canvas and documents

A layered canvas with object identity, not a flattened image.

Available
  • Layered documents with groups, nesting, and object selection
  • Transform handles, numeric transforms, and path-node editing
  • Guides, grid, snapping, and zoom controls
  • History, undo/redo, journal, and command replay
  • Mask stacks and live effect stacks that remain editable
  • Native .fw.png read/write with unknown-node preservation

02 · Vector

Paths that stay paths

Contours, Bézier handles, primitive shapes, booleans, gradients, fills, and strokes are native document objects — not rasterized on import.

Path editing

Node and handle editing, contour joins, and precise geometry operations.

Shapes & booleans

Primitive shapes with union, subtract, intersect, and combine operations.

Paint & strokes

Solid and gradient fills, stroke alignment, caps and joins, and opacity.

Arrangement

Align, distribute, reorder, group, and transform selections numerically.

SVG interchange

SVG import and export through the same vector document model.

Gradient control

On-canvas gradient handles with stop editing and direction control.

03 · Bitmap

Pixels without
leaving the document.

Bitmap objects sit in the same layer stack as vector objects. Paint, retouch, and select pixels while the rest of the artwork stays vector.

Available
  • Paint and retouch tools
  • Pixel-selection modes and marquee workflows
  • Bitmap objects and raster composition
  • Import raster images into a new document
document.manifest
layers: [
  { kind: "vector", name: "flame outline" },
  { kind: "bitmap", name: "paper texture" },
  { kind: "text", name: "title" }
]
// one stack, three mediums

04 · Type

Text and symbols

Editable text objects with rich attributes, plus reusable symbols for repeated artwork.

Available

Text objects

Rich text attributes, in-canvas editing, and text that remains editable in the document.

Available

Symbols

Definitions and instances, nested symbol workflows, and nine-slice guides for scalable UI parts.

Preview

Style reuse

Shared fills, strokes, and effects across objects; the editing UI is still being fleshed out.

05 · Effects

Non-destructive
by default.

Live effects and filters run through the compositor, so a glow or blur can be adjusted or removed later instead of being baked into pixels.

Available

Live effects

Effect stacks attached to objects, reorderable and removable.

Filters

A filter surface backed by the same compositor used for rendering.

Masks

Mask stacks with editable mask objects and vector or bitmap masks.

Blend modes

Object-level compositing with blend controls in the document model.

06 · Interchange

Formats with direction,
not just a logo wall.

Each format has a documented direction and known limits. The compatibility matrix lists them per format, including what round-trips.

07 · Automation

Drive the editor
from outside it.

The GUI and every automation surface call the same registered commands, so a scripted convert behaves like the equivalent manual edit.

Available

Headless CLI

Inspect, convert, export, and import documents without opening the editor.

shell
firecraft-cli info artwork.fw.png
firecraft-cli convert in.fw.png out.fw.png
firecraft-cli export artwork.fw.png out.webp
Preview

Scripting, bridge, MCP

ExtendScript-compatible .jsf execution, a browser postMessage bridge, and a Model Context Protocol server.

These surfaces work end to end but their public contract is still settling; expect changes between releases.

08 · Foundations

A Rust engine
with one authority.

One document model and one command registry sit under the desktop shell, the WebAssembly build, the CLI, and the automation surfaces. Rendering has a deterministic CPU reference path and a GPU-accelerated interactive path.

  • unsafe is forbidden workspace-wide
  • Hostile input returns typed errors instead of aborting
  • WASM build checked on every gate
  • Corpus fixtures pinned by digest for round-trip identity

Crate layout

workspace · 15 crates
// foundations
fwpng geom color raster
// engines
doc vector filters text
// rendering + shells
compose gpu engine app
// codecs + automation
io scripting webexport app-cli
i

Known limits, stated plainly. Some commands are reachable through the command palette or automation before they have a menu item or polished inspector. Remaining panel work includes Optimize, Common Library, CSS Properties, Find and Replace, and Slices. The authoritative list is the repository's gap register ↗.

Not a CS6 clone

The goal is the productive hybrid workflow, not a pixel-identical reproduction of an application Adobe no longer ships.

Not a painting suite

Brush engines and pressure-sensitive painting are outside the current scope; bitmap editing is aimed at web graphics work.

Not finished

Active development continues. Check the release notes for what changed and the roadmap for what is next.
