The Shell module carries every menu action, every keyboard shortcut, every panel toggle, every selection operation, and every export/import path in one impl block. run_action is a match arm with 10 variants; run_sel has 40+; run_shell has 50+. The interface surface is wide: 8 public methods, 7 pub(super) methods, 20 stubs for #[cfg(not(feature = "native"))], and 10 dialog state fields that duplicate in Shell what each Dialog struct already carries.

The test module (lines 3084–7569) is itself 4 485 LOC — more than half the module — and every test reaches through gui_shell() to seed a full editor + dialog stub + memory filesystem. Testing a single shortcut requires instantiating the entire shell.

Extract a command dispatch module. Move run_action, run_document, run_shell, run_sel, run_arrange into a separate shell/dispatch.rs with one public interface: impl Shell { fn dispatch(&mut self, action: &Action) }. The dispatch module owns the match arms; the shell struct owns only state.

  • Interface shrinks; implementation absorbs the wrappers
  • Tests hit one dispatch interface
  • Locality: shortcut logic concentrates in one module
  • Delete 20 stub functions from the non-native shim

Understanding the right-hand dock requires bouncing between panels.rs (5 276 LOC: Properties, Pages, States, Layers, History, Styles, Color Mixer, Library) and panels_web.rs (1 730 LOC: Auto Shapes, URL, Behaviors, Slices). The web panels reference slice_editor for their behavior/action mapping, creating a three-module seam. The split is platform-based, not responsibility-based: panels.rs owns desktop panels and panels_web.rs owns web panels, but both are egui-drawing modules with zero runtime variation between native and wasm builds.

Consolidate panels.rs + panels_web.rs into one module. Remove the platform split: all panel content lives in panels.rs. The cfg(feature = "native") gates on these modules exist because web panels reference desktop-only types — move those types instead of gating the panel module.

  • One module to understand instead of two
  • Interface: single impl Shell block for all panels
  • Locality: Behaviors panel + slice_editor mapping in one read
  • Web panels and desktop panels are identical in this build

file_operations.rs opens and saves documents, runs scripts, imports raster files — all gated behind cfg(feature = "native"). It calls self.dialogs.open_path() and self.fs.read_file() from the injected platform traits. dialogs.rs defines the dialog types (NumericTransformDialog, FeatherDialog, CanvasSizeDialog, CanvasColorDialog, ImageSizeDialog, ExportDialog) and implements the EnvDialogs adapter over engine::platform::Dialogs.

The seam between dialogs and file_operations is real: every file operation asks the dialog for a path. But the interface of dialogs.rs is nearly as complex as its implementation: it carries the full export format pipeline (12 formats, M11 web workflows) and 6 dialog structs with their default values, plus the EnvDialogs platform adapter.

Merge dialogs.rs into file_operations.rs. The dialog type definitions and the file operation functions belong to the same responsibility: the file I/O seam. Move dialog types and EnvDialogs into file_operations.rs. Keep the engine::platform::Dialogs trait as the external adapter; the rest concentrates the file I/O seam.

  • File I/O seam concentrates in one module
  • Delete one shallow module; depth moves to file_operations
  • One adapter (EnvDialogs) now alongside its use site

Top recommendation

Strongest

Collapse the Shell dispatch monolith

The 7 820 LOC shell module with 240 functions and 4 485 LOC of tests is the deepest structural problem in the shell. Every user-facing command flows through run_action, which branches into run_document, run_shell, run_sel, and run_arrange — four match arms that together cover the entire menu system. Extracting the dispatch logic into a dedicated module reduces Shell by more than half and gives each command path its own test surface. The deletion test is decisive: removing dispatch concentrates exactly one responsibility (command dispatch) in a deep module instead of scattering it across mod.rs.
