# FireCraft audit — 2026-11-13

Read-only audit of `main` @ `1ac3dbc` (v0.2.5 + #118–#135), all 34 remote
branches, the 4 open PRs, the 70 open issues, the planning docs, the code,
the live deployment and the release state. These findings feed the
[climb](README.md). Status words: **Verified** = measured with a command;
**Most likely** = strong evidence, not executed.

## 1. Verdict

The engine is in good shape:
- 177k lines of Rust;
- 1,810 tests;
- zero `unwrap`/`panic` in non-test code;
- 19 of 20 corpus `.fw.png` files round-trip byte-identically;
- 253 registry commands;
- CS6 tools, filters, blend modes, symbols, slices and keymap are largely
  done.

The project drifted on three fronts.

1. **Process drifted from product.**
   - Since 2026-11-01, about 29 of 53 commits on `main` were
     docs/release/CI/brand/changelog work, and about 13 were features.
   - Release work alone spawned 61 T27 tickets, plus RP-00…09 and
     WP-00…07 for the same deliverables.
   - Yet no Windows or macOS artifact has ever been built, and nothing is
     signed.
2. **Status is restated in roughly eight documents that disagree** (§4).
   No single doc can be trusted for "what is next".
3. **The production web target is not production.**
   - The live deploy matches no commit.
   - Deploys are manual.
   - The WebOS bridge answers any origin.
   - There is no PWA, no File System Access API, and no OS clipboard.
   - The core Fireworks export (PNG8/PNG24) is missing.

## 6. Code quality (Verified: source reads; build not run, no toolchain on this host)

- **Size:**
  - engine 50.7k, app 32.9k, xtask 13.6k, io 12.5k, compose 10.1k,
    doc 9.5k lines.
  - 18 `.rs` files exceed 2,000 lines.
  - Worst offenders:
    - `app/src/shell/mod.rs`: 6,614 lines, about 40 % inline tests;
      `run_sel` is about 563 lines and `run_shell` about 444.
    - `app/src/editor.rs`: 5,622 lines.
    - `app/src/menus.rs`: 4,364 lines.
  - Seven `engine/src/catalog/*` files run 2.7–4.5k lines, but they are
    data-like.
- **Banned constructs:** `unwrap`/`expect`/`panic!`/`todo!`/
  `unimplemented!`/`unreachable!` in non-test code: **0**. There are 13
  justified `#[allow]`s.
- **Lint hole:**
  - `crates/io/Cargo.toml` sets `unsafe_code = "allow"` for the whole crate,
    although only `io/src/webp_lossy.rs` (libwebp FFI) needs it.
  - Its own lint table also drops four workspace denies: `todo`,
    `doc_markdown`, `must_use_candidate`, `needless_pass_by_value`.
- **Phantom layer entries:** `xtask/src/layers.rs` lists the crates `ops`,
  `gpu`, `automation` and `testkit`, none of which exist.
- **Toolchain:**
  - CI pins rustc **1.99.1** (`infrastructure/docker/ci-rust.Dockerfile`,
    GitHub workflows).
  - There is no `rust-toolchain.toml`, so agents get whatever rustc they
    have.
  - A coverage gate already runs inside `xtask ci` (`xtask/src/coverage.rs`, cargo-llvm-cov): line floor 81.1 %, function floor 78.7 %, measured 2026-10-30. Per-crate floors do not exist. PR #142 (decision 0103) records that the measurement shifts with the toolchain.
- **Wasm:**
  - 21.27 MB raw and 7.38 MB gzipped (SESSIONS.md) — about double the
    10.87 MB recorded at M13.
  - Decision 0090 raised the ceiling (25 MB warn / 50 MB hard) instead of
    trimming.
- **UI dispatch:**
  - Every action funnels into `Shell::run_command` → `editor.apply(id, json)`.
  - `xtask reachability` computes the unreachable list but **does not print
    it**.

## 8. Web, WebOS and release (Verified: curl of the live site, workflow files, `gh release view`)

**Live site**
- Serves bundle `2274ac8c2925b61d` with `appinfo.json` 0.2.5. This matches
  neither the v0.2.5 release zip nor a rebuild of the tag.
- The deploy step in `release.yml:382` is commented out, so deploys are
  manual.
- `appinfo.json` icon paths return HTML, because the SPA fallback hides
  missing assets.
- No web manifest, no service worker, no loading indicator.

**Bridge** (`web/src/main.rs`)
- Supports ping/ready, openDocument, apply, exportPng and exportDocument.
- Replies go to `"*"` (line 42).
- There is no inbound origin check, no protocol version, no request IDs, no
  capability handshake and no payload cap.

**Browser I/O**
- Open uses a hidden `<input>`; Save is a Blob download.
- No File System Access API and no OS clipboard image paste.
- Autosave goes to `localStorage` as base64, subject to the browser's
  storage quota.

**v0.2.5 assets**
- Published: Linux desktop tar.gz, CLI tar.gz, .deb, web zip,
  MANIFEST.sha256.
- Recipe only, never run: AppImage, Flatpak, Windows zip + Inno, macOS DMG.
- Not in v0.2.5, but already wired on `main`: `release.yml` builds the source archive (`dist --source`), the CycloneDX SBOM (`dist --sbom`), `RELEASE_SHA256.txt` and `release-manifest.json`. These ship with the next tag. Still missing: signing and attested build provenance (`actions/attest-build-provenance`).
- Deferred: Android, RPM, ARM.
- **Key insight:** the "off-fleet" Windows/macOS blockers (B-8/B-11/B-12)
  can be solved with GitHub-hosted `windows-latest` and `macos-14` runners.
  `ci.yml` already runs on GitHub, so no hardware is needed.
