## Measured size cost in the web bundle

The pack's cost is measured, not estimated: the web bundle is built twice
from the same tree, once as shipped and once with the runtime icon table
emptied, and the two bundle sizes are differenced. The record lives in
`docs/planning/icon-wasm-cost.tsv`.

| Arm | Source | Web bundle (B) |
|---|---|---:|
| with the icon pack | `main@55a0e541` | 15,592,313 |
| without the icon table | `main@55a0e541, ICONS emptied` | 15,560,629 |
| **the icon pack's cost** | | **31,684** |

The bundle that carries the pack is 15,592,313 B against the 25,000,000 B
investigation threshold and the 50,000,000 B hard ceiling (decision 0090), so the pack
costs 0.203 % of a bundle that stays under both.

## How the survey stays true

- `cargo run -p xtask -- icon-survey` regenerates this file from the assets on
  disk, the attribution ledger, and the measured-cost record; the CI
  `generated-docs` job compares the committed file with what the generator
  produces, so a hand-edit is a red build.
- An icon with no attribution row fails the generator — the set-level ledger
  row only covers the set while every file in it is named by the set.
- The `Embedded` column is read from the runtime table: an icon that is not
  embedded does not reach the binary, and an icon that is embedded without
  a ledger row is a licence defect.
