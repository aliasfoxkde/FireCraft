# Phase B — Binary Optimization, Minification, Compression & Modular Folder Layout (`T31` + `0090`)

> **Why this phase exists:** Directly honors the maintainer's request to **shrink WASM and native binaries** (stripping names/debug sections, minifying/mangling JS, Brotli + Gzip compression, removing redundant dependencies) AND **split runtime assets/extensions/examples/libraries/optional modules into clean folders** for maintainability and fast initial browser/WebOS load.
> **Authority:** [`docs/tasks/T31-modular-packaging-and-wasm-size.md`](../../tasks/T31-modular-packaging-and-wasm-size.md) · [`docs/decisions/0090-wasm-bundle-size-policy.md`](../../decisions/0090-wasm-bundle-size-policy.md)
> **Rule:** Every optimization MUST include a **same-SHA before/after table** measuring raw bytes, `.gz` (level 9), `.br` (level 11), JS glue, HTML, and startup/interactive latency. Keep only changes that demonstrably improve size/load without breaking editing, diagnostics, or bridge smoke!

---

### `L-B1` `[LUNA]` Reproducible WASM + Native Size & `twiggy` Profiler Baseline (`T31.1`)

- **Goal:** Establish the exact byte-for-byte size baseline on one named commit before changing a single profile flag or splitting a single file.
- **Pre-check:**
  ```bash
  ssh fedora 'export PATH="$HOME/.cargo/bin:$PATH"; which cargo trunk wasm-opt twiggy brotli gzip 2>&1 || true'
  ```
- **Steps:**
  1. Ensure `twiggy` and `brotli` are available on `fedora` (if `twiggy` is missing, install `cargo install twiggy --locked` on `fedora`).
  2. Build on `fedora`:
     - Web release bundle: `cargo run -p xtask -- dist --web`
     - Linux desktop + CLI release: `cargo build --release -p app -p app-cli`
  3. Run `twiggy top -n 40 dist/web/*_bg.wasm` and `twiggy dominators -r 25 dist/web/*_bg.wasm`.
  4. Compress staged `.wasm`, `.js`, `.html` with `gzip -9 -k` and `brotli -q 11 -k` to record exact baseline transfer bytes.
  5. Write a deterministic report to `docs/planning/generated/size-baseline.md` containing:
     - Commit SHA, Rust/Trunk/wasm-bindgen/wasm-opt versions.
     - Table of raw, `.gz`, and `.br` bytes for `.wasm`, `.js`, `.html`, and total initial transfer.
     - Native `firecraft` and `firecraft-cli` binary sizes (unstripped vs stripped).
     - Top 25 `twiggy` size contributors (quantifying exact bytes from `resvg`/`usvg`/`tiny-skia`, fonts, `egui`, `io` codecs, `compose`, etc.).
- **Verify:**
  ```bash
  test -s /var/tmp/firecraft-int-1.0/docs/planning/generated/size-baseline.md && grep -q "twiggy" /var/tmp/firecraft-int-1.0/docs/planning/generated/size-baseline.md
  ```

### `L-B2` `[LUNA]` High-ROI WASM & Binary Size Optimization Pass (`T31.2`)

- **Goal:** Execute the highest-ROI Rust/WASM size reductions backed by `L-B1`'s `twiggy` data, measuring EVERY lever independently.
- **Pre-check:**
  ```bash
  grep -n "egui_extras\|resvg\|default_fonts\|LiberationSans" /var/tmp/firecraft-int-1.0/crates/app/Cargo.toml /var/tmp/firecraft-int-1.0/web/Cargo.toml /var/tmp/firecraft-int-1.0/crates/text/src/lib.rs
  ```
- **Steps:**
  1. **Lever 1 — Eliminate runtime `resvg`/`usvg`/`tiny-skia` WASM bloat WHILE KEEPING Phosphor Icons!**
     - Currently `egui_extras/svg` pulls `resvg` + `usvg` + `tiny-skia` + `fontdb` into the WASM binary purely to rasterize static Phosphor SVGs at runtime.
     - Replace runtime SVG parsing in `crates/app/src/shell/icons.rs` with a lightweight **build-time** Phosphor delivery path (either a subsetted Phosphor icon font `.ttf` ~30–60 KB OR a pre-baked multi-DPI alpha/SDF sprite atlas generated by `xtask icon-atlas` from `assets/icons-phosphor/*.svg`!).
     - This preserves **100% authentic, razor-sharp Phosphor Icons** across desktop & WASM while dropping megabytes of runtime `resvg`/`usvg`/`fontdb` WASM bytecode! Keep `xtask icon-survey` green and verify crisp rendering in both desktop and Playwright screenshots.
  2. **Lever 2 — Font deduplication audit:**
     - Measure the exact byte cost of `eframe`'s `default_fonts` vs `crates/text/assets/LiberationSans-{Regular,Bold}.ttf` (824 KB) in `twiggy`. Remove duplicate font weight embeds only if text rendering tests and screenshot checks stay 100% crisp.
  3. **Lever 3 — Web-only Rust release profile & `wasm-opt` name/debug stripping:**
     - In `xtask/src/dist.rs::stage_web()`, evaluate and benchmark web-only env overrides (leaving native release profile untouched unless separately proven):
       - `CARGO_PROFILE_RELEASE_OPT_LEVEL=z` (already set)
       - `CARGO_PROFILE_RELEASE_LTO=fat`
       - `CARGO_PROFILE_RELEASE_CODEGEN_UNITS=1`
       - `CARGO_PROFILE_RELEASE_PANIC=abort`
       - `CARGO_PROFILE_RELEASE_STRIP=symbols`
     - In `web/index.html`, pass Binaryen optimization + debug/name stripping flags via `data-wasm-opt-params="--strip-debug --strip-dwarf --strip-producers --dce --vacuum"` (verify exact Trunk syntax against the pinned Trunk version on `fedora`!).
     - Note: This strips internal debug/name sections from WASM bytecode cleanly (the real compiled-WASM equivalent of stripping variable names).
  4. **Lever 4 — Native desktop symbol stripping (optional separate debuginfo):**
     - Measure Linux & Windows release binary size with `strip = "symbols"` vs split debuginfo; keep crash-reporting ergonomics documented.
  5. Update `docs/planning/generated/size-baseline.md` with the exact same-SHA before/after table for each lever. Keep ONLY levers that reduce size AND pass `xtask dist --web` bridge smoke!
- **Verify:**
  ```bash
  ssh fedora 'export PATH="$HOME/.cargo/bin:$PATH"; export CARGO_TARGET_DIR=/var/tmp/firecraft-target-fedora; cd /var/tmp/firecraft-int-1.0-git && git pull --ff-only && cargo test -p app && cargo test -p xtask && cargo run -p xtask -- dist --web'
  ```

Add a deterministic JS minifier/mangler pass in `stage_web()` (using `esbuild --minify` or `terser --compress --mangle` when available, or Trunk's `data-minify` where supported) to shrink and mangle local variable names in generated `firecraft-web.js` glue without breaking the `postMessage` WebOS bridge exports! ### `L-B4` `[LUNA]` Modular Runtime Folders — Split Out `examples/` and `libraries/`

- **Goal:** Move non-essential embedded sample content, styles, symbols, and swatches out of monolithic compiled binaries into clean, maintainable, versioned top-level folders loaded at runtime on desktop and fetched on demand on WASM:
  - `examples/` — editable `.fw.png` sample documents + `examples/manifest.json`
  - `libraries/` — reusable symbol libraries (`libraries/symbols/`), style libraries (`libraries/styles/`), color swatch palettes (`libraries/swatches/`), and `libraries/manifest.json`
- **Pre-check:**
  ```bash
  ls -la /var/tmp/firecraft-int-1.0/assets/library /var/tmp/firecraft-int-1.0/assets/styles
  ```
- **Steps:**
  1. Create `examples/` containing `examples/manifest.json` and 3–4 small, genuine `.fw.png` example documents generated cleanly through `firecraft-cli` or `demo.rs` (e.g., `studio-showcase.fw.png`, `ui-card-kit.fw.png`, `web-banner-animated.fw.png`, `icon-grid.fw.png`) — zero Adobe assets!
  2. Create `libraries/` organizing shipped `.fw.stl` styles, Common Library symbol packs, and swatch palettes with `libraries/manifest.json` (keep any existing `assets/` paths working or symlinked/updated consistently with tests).
  3. Implement a clean resource discovery loader (`crates/app/src/resources.rs`):
     - **Desktop:** searches executable-adjacent `./examples`, `./libraries`, then user data directory, then workspace root (dev mode).
     - **WASM:** fetches `examples/manifest.json` and `libraries/manifest.json` lazily on demand via `fetch()` when the user opens `File ▸ Open Example`, Welcome Screen Examples, Styles, or Common Library — ZERO bytes downloaded at startup!
  4. Wire `File ▸ Open Example ▸ ...` and the Welcome Screen's example cards to load from `examples/`.
  5. Update `xtask/src/dist.rs` (`stage_web` copies `examples/` and `libraries/` as static folders; `dist --native` bundles `examples/` and `libraries/` alongside `bin/`).
  6. Add unit tests for manifest parsing, missing-folder graceful fallback, and path-traversal rejection (`../` refused!).
- **Verify:**
  ```bash
  ssh fedora 'export PATH="$HOME/.cargo/bin:$PATH"; export CARGO_TARGET_DIR=/var/tmp/firecraft-target-fedora; cd /var/tmp/firecraft-int-1.0-git && git pull --ff-only && cargo test -p app && cargo test -p xtask && cargo check --target wasm32-unknown-unknown -p firecraft-web && cargo run -p xtask -- layers && cargo run -p xtask -- aegis'
  ```

### `L-B5` `[LUNA]` Modular `extensions/` Folder & Versioned Capability Manifest (`T31.4`)

- **Goal:** Create a clean, maintainable `extensions/` folder with a versioned, sandboxed extension contract shared by desktop and WASM (no unsafe Rust DLL/dylib ABI!).
- **Pre-check:**
  ```bash
  ls -la /var/tmp/firecraft-int-1.0/crates/scripting/
  ```
- **Steps:**
  1. Define and document the `extensions/manifest.schema.json` contract (`docs/decisions/0131-extension-package-contract.md`):
     - Fields: `schema: "firecraft-extension/v1"`, `id`, `name`, `version`, `api_range`, `entry`, `kind` (`"jsf"` or `"command-pack"`), `capabilities` (explicit list, e.g. `["document.read", "document.mutate", "export.css"]`), `sha256`.
  2. Implement `crates/app/src/extensions.rs` (desktop discovery from `./extensions/` + user extensions dir; WASM lazy fetch from `./extensions/index.json`):
     - Strict validation: reject incompatible `api_range`, invalid JSON, path traversal, or undeclared capabilities; enforce statement/time sandbox limits on execution.
     - UI management row (`Commands ▸ Manage Extensions...`) to inspect, enable/disable, and run installed extensions.
  3. Ship 2 real, useful first-party extensions under `extensions/` (no fake placeholders!):
     - `extensions/css-design-tokens/` (exports selected objects' fills/strokes/typography as CSS custom properties)
     - `extensions/batch-social-presets/` (creates standard web/social artboard pages cleanly via engine commands)
  4. Add unit tests covering valid install/run, incompatible API rejection, malformed manifest rejection, and undeclared capability refusal.
- **Verify:**

### `L-B6` `[LUNA]` True Lazy WASM Feature Module Split (`T31.3`)

- **Goal:** Using `L-B1`'s `twiggy` dominators report, extract the heaviest non-startup optional feature (e.g., optional PSD/TIFF/WebP/SVG import-export codecs OR optional `.jsf` scripting worker) into a separate lazy-loaded WASM module under `dist/web/modules/<feature>.wasm` that is **NOT fetched at startup**.
- **Pre-check:**
  ```bash
  cat /var/tmp/firecraft-int-1.0/docs/planning/generated/size-baseline.md | head -n 60
  ```
- **Steps:**
  1. Select the #1 non-core feature by measured bytes from `L-B1` (never split core document open/save, vector/bitmap editing, undo, or recovery!).
  2. Build it as a separate small `wasm32-unknown-unknown` crate/module under `dist/web/modules/` with content-digest filename and `.gz`/`.br` sidecars.
  3. Load it asynchronously via JS bridge (`WebAssembly.instantiateStreaming`) ONLY when the user triggers that feature, with explicit loading status and graceful offline error handling (core editing MUST stay alive if the lazy fetch fails).
  4. **Network Waterfall Proof:** Run a Playwright test that records all network requests during startup (asserting `modules/*.wasm` is **ABSENT** from startup requests!), then triggers the optional feature and asserts the module fetches once, executes cleanly, and caches.
  5. Update `docs/planning/generated/size-baseline.md` with initial vs deferred transfer totals and cold/warm latency.
- **Verify:**
  ```bash
  ssh fedora 'export PATH="$HOME/.cargo/bin:$PATH"; export CARGO_TARGET_DIR=/var/tmp/firecraft-target-fedora; cd /var/tmp/firecraft-int-1.0-git && git pull --ff-only && cargo run -p xtask -- dist --web && npx playwright test web/test.spec.ts'
  ```
