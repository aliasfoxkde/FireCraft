# v0.2.5-dryrun.3 — DISPOSABLE REHEARSAL, NOT A RELEASE

> **This tag is a disposable dry run.** It exists to prove that the
> draft-release path works end to end before anyone cuts a production
> tag (issue #99, campaign row T27-19). It is **not** a release of
> FireCraft, it is not published, and it must not be downloaded by
> anyone as a product. The version string carries `-dryrun.3` for
> exactly that reason.

## What this rehearsal covers

The release workflow has never produced a release: the artifact upload
step carried a broken argument form, so the "draft release" the
artifact matrix claimed was never reachable. This run exercises the
whole path — tag push → native build → web build → checksums → asset
upload → draft release creation — against the tree at `main`
(`18c5a52`) with only the version stamps changed.

Two earlier rehearsals stopped before the draft release was created,
and each exposed a defect in the rehearsal's own stamp rather than in
the release path:

- **`v0.2.5-dryrun.1`** (run `42934367397`) stopped in "build
  artifacts": `xtask` declares its path dependency on `compose` with a
  version requirement, and a caret requirement `^0.2.5` does not match
  a prerelease, so cargo refused to resolve the workspace.
- **`v0.2.5-dryrun.2`** (run `42935594312`) stopped in the same job, in
  `xtask`'s `build_deb`: the stamp had replaced the whole
  `Version: 0.2.5-dryrun.1` line of `packaging/deb/control` with the
  bare version, dropping the field name. `build_deb` looks the pinned
  version up by its `Version: ` prefix, so it reported
  "packaging/deb/control: no Version field". The stamp now replaces
  only the field's value.

The Debian version parser accepts a prerelease version in the
`Version:` field — `dpkg-deb --build` and `dpkg -i` both take
`0.2.5-dryrun.3` on Debian 12 without complaint — so the version
string is not what the second rehearsal tripped over.

## After the rehearsal

The draft release and the tag are deleted once the assets have been
verified. The receipt — run id, job ids, asset list, digests, and every
defect the run exposed — is recorded in `docs/release/` and on issue
#99. Nothing about this rehearsal changes the production release path;
it only proves the path exists.
